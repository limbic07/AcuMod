# Acumod 文档入口

本目录记录 Acumen MOD manager 的产品范围、技术架构、开发方式和安全边界。文档优先服务两件事：

1. 让后续开发前能快速确认“现在项目到底怎么运转”。
2. 把尚未确定的技术细节显式列出来，避免在实现时临时猜测。

## 当前阶段

任务资料现有 354 条；已验证的解锁链覆盖本体和冰原已分配、可选任务，以及可唯一定位的活动、斗技场和挑战任务。知识包包含 180 条可唯一核验的前置任务关系和 466 条等级、捕获/发现、NPC、剧情、活动开放或任务前置等解锁条件。外部数字 ID 不会单独用于绑定本地任务；未验证的名称和交货委托条件不会被猜测成关系。

当前开发阶段已经从传统管理器增强转入 AI Agent 知识能力：

- **已完成实现**：AI Slice 1“本地只读助手”，包括 DeepSeek V4 设置、流式对话、Markdown 回答、本地 MOD/冲突/游戏目录/术语只读工具和完整列表分页。

- **已完成实现**：AI Slice 3“全部 MOD 冗余文件清理”已改为完整文件盘点、本地双信号规则分流和模糊文件组 AcuAI 审核，并复用既有逐项选择、部署排除、冲突版本恢复和清理记录恢复。
- **已完成实现**：AI Slice 4“联网搜索与 Nexus 安装”，包括 DeepSeek 官方联网搜索、来源白名单、Nexus 凭据与文件列表、Premium 受控下载计划、真实进度和传统导入桥接。

- **实现原则**：用同一套“术语解析 -> 结构化查询/全文检索 -> 证据核验 -> 回答生成”处理事实查询、开放式推荐、排查和规划问题；不为“配装”“素材路线”等单个问题各写一套流程。
- **知识库制作**：由项目维护者负责采集、清洗、校验、打包和发布，用户只需在设置中安装或更新可选知识包，不需要自行整理 SQLite 或编写规则。

详细验收范围以 `docs/features.md` 的 AI Slice 1 至 Slice 6 为准；`docs/README.md` 只维护当前截点和顺序，不重复全部实现细节。

后台任务与进度切片已完成：刷新、导入、启用、禁用、卸载、一键还原、冲突应用和模型改绑均通过统一后台任务入口执行。界面在顶部下方展示当前阶段、文件级进度和耗时；`AcumodData/mods/workspace-snapshot.json` 缓存 MOD 列表、分类、冲突报告和有效部署路径索引。启动、普通导入、启停、卸载、批量操作、模型改绑和冲突应用均增量更新快照，操作后不再扫描全部 manifest；名称、备注和分类编辑直接局部更新前端状态。只有用户点击“刷新”、首次建立快照、schema 升级、狩技盒子全量状态同步或一键还原等真正全局操作才读取整库。冲突组上移/下移只保存当前组顺序并更新缓存。任务不提供取消，重任务按单任务串行执行。

狩技 MOD 盒子的只读扫描、批量导入和自动状态同步已实现：导入页读取 `config.ini`、`Mods_582010/<模块 ID>/info.xml` 和 `files/`，默认选择全部模块导入本地库。批量导入复用一次本地清单索引，先按已保存的盒子来源关联，再按部署路径与完整文件内容关联重复 MOD；同名但内容不同的模块会独立保存。导入完成后，后台逐文件显示游戏实际状态检测进度，自动显示“已启用”或“未启用”；已启用 MOD 可附带“部分被冲突覆盖”提示。状态同步只写 Acumod 元数据，不修改游戏目录，也不要求用户逐个选择或确认；用户可随时手动重新检测。

本次元数据迁移无须用户操作：旧 `categories.json` 会在首次读取时升级到 schema 3，原有分类保留为顶级分类；旧 `conflict-orders.json` 会升级到 schema 2 并反转每个组的存储数组，以在“最上方最终覆盖”的新界面语义下保持原本实际生效的 MOD 不变。

## 多配置移除迁移说明

Acumod 已确定只维护一套当前部署状态，不再提供多配置、状态快照或配置切换。升级到这一版本不需要执行数据转换，因为当前实际状态本来就由下列文件保存：

- `AcumodData/mods/installed/<mod_id>/manifest.json`：该 MOD 是否启用，以及 Acumod 曾部署到游戏目录的文件记录。
- `AcumodData/mods/installed/conflict-orders.json`：每个冲突组当前的 MOD 优先级，最上方项目最终覆盖。
- `AcumodData/mods/mod-library-order.json`：MOD 库的手动浏览顺序。

因此，已导入的 MOD、当前实际启用状态、部署记录和冲突排序会继续生效；不再可用的是旧多配置中额外保存的命名快照和配置切换记录。

旧版本留下的 `AcumodData/mods/profiles.json` 不是当前状态来源。程序不会读取、转换、写入或自动删除它，用户无需为升级执行任何操作。确认不再需要旧快照后，用户可自行保留该文件，或在退出 Acumod 后先备份再手动清理；不要误删 `installed/` 下的 manifest 或 `conflict-orders.json`。

## 已确认技术事实

- 应用短名：Acumod；界面完整名称：Acumen MOD Manager。
- 项目包名：`acumod`。
- 当前版本：`0.1.0`。
- 桌面框架：Tauri 2。
- 前端：Vue 3 + TypeScript + Vite。
- 脚本和包管理：npm。
- 后端：Rust 2021 edition。
- 前后端通信：`@tauri-apps/api/core` 的 `invoke()` 调用 Rust `#[tauri::command]`。
- 序列化：Rust 使用 `serde` / `serde_json` 返回结构化 DTO。
- 当前插件：`tauri-plugin-opener` / `@tauri-apps/plugin-opener`。
- Tauri identifier：`com.acumod.app`。
- 开发端口：Vite 固定使用 `1420`，Tauri devUrl 为 `http://localhost:1420`。
- MVP 配置、MOD 元数据、启用状态、排序和部署记录继续使用 JSON；Slice 5 起仅知识包和全文检索使用只读 SQLite，不迁移传统管理器数据。
- 存储位置：`AppData` 只保存 `config.json` 等小配置；MOD 库、导入暂存和任务耗时日志放在软件目录旁的 `AcumodData/` 下，日志文件为 `AcumodData/logs/operation-timings.log`。
- MOD 部署方式：只使用复制式部署。安装时在 Acumod 软件目录保存一份 MOD；启用时复制到 MHW 游戏目录；禁用时删除游戏目录中的已部署副本；卸载 MOD 时删除软件目录中的 MOD 副本。
- MOD 导入方式：第一版支持文件夹导入，以及 `rar`、`zip`、`7z` 压缩包导入；当前压缩包导入使用随 Acumod 打包的 7-Zip 解包组件，不要求用户另行安装 7-Zip。支持递归识别两层、最多 32 个内嵌压缩包；用户可多选候选并作为分支组或独立 MOD 导入，每个不同分支只长期保存一份本地库副本。
- MOD 导入识别：优先识别 `nativePC`；缺少 `nativePC` 但出现常见 nativePC 内部目录时自动补成 `nativePC/...`；用户直接选择 `plugins`、`weapon` 等内部目录时保留目录名并映射到 `nativePC/<目录名>/...`；仍无法识别时允许用户确认按游戏根目录相对路径导入。
- MHW 替换识别：`references/mhwi-data/curated/model-index.json` 内置维护武器、防具、发型、随从装备、猎虫、挂件、NPC、投射器/飞翔爪和人物语音索引；路径规则额外识别 `nativePC/plugins` 为“插件”，并从规范 Wwise `.nbnk` 文件名识别 14 种“武器语音·武器类型”。只把规范资源根目录中的文件显示为游戏内替换目标，`vfx/mod` 等附属特效资源仍部署但不冒充装备替换。飞翔爪只在 MOD 同时包含模型和匹配 `.evam` 时显示关联防具，孤立 `.evam` 不产生识别结果；`Assets/gm/gm000` 弹药资源不属于该识别范围。
- 单一当前配置：每个 MOD manifest 的 `enabled` 与 `deployedFiles` 表示当前实际部署状态，`conflict-orders.json` 保存冲突组优先级，最上方的已启用 MOD 最后覆盖。旧版本留下的 `profiles.json` 不再读取或写入，也不会被程序自动删除。
- MVP 不包含下载、更新、AI Agent 和模型改绑；MVP 后的 Slice 14 支持武器、防具、随从防具、投射器和发型改绑，人物语音继续仅识别。
- 当前阶段能力：基于 MHW 文件 ID 表为新导入 MOD 生成初始分类，并支持多分类编辑、搜索、筛选和浏览排序；导入顺序、名称、分类和替换信息均可切换升序或倒序，手动顺序继续由拖拽维护；防具改绑目标及分类相同的防具 MOD 使用游戏内外观装备菜单实际顺序；稳定识别脸型、怪物、噗吱猪服装、家具及玩家/随从附件，并在冲突组中提示相同替换目标。
- 游戏文本语言：设置页可在简体中文和繁體中文间切换武器、防具等游戏名称。繁中索引按同一游戏文本键配对生成，不做机械字形转换；切换只更新 `AppData/config.json` 的小配置并立即刷新显示，不扫描 MOD 或改写本地库。
- 当前 manifest schema 17：保留 schema 10 引入的改绑选择、schema 13 的 `.evam` 关联识别、schema 14 的 `categoryIds[]` 多分类和 schema 15 的盒子来源及观察所得部署记录；模型识别规则版本 16 继续负责插件与武器语音识别，schema 17 新增部署排除记录。本地 MOD 原始副本不改写，有效部署计划统一驱动复制、冲突检测和排除项恢复，并精确修正 MRL3 贴图路径与 EVAM 飞翔爪绑定。
- MOD 分支组：`AcumodData/mods/branch-groups.json` 只保存组名和成员 ID；每个分支仍使用独立 manifest、文件副本、启用状态和冲突顺序。只剩一个成员时自动拆组。MOD 库按一级表格项汇总显示组分类和替换信息，展开后使用层级序号与明确组边界；组行可将所有成员作为连续块拖拽，也可用三态分类菜单批量增删或清空成员分类。自动分组对单文件同路径 MOD 直接生成候选，多文件 MOD 采用高路径覆盖率、全成员两两校验和真实共同文件交集，且超过 16 项的候选不显示；用户勾选后才调用现有分支组创建命令。
- MOD 库顺序：`AcumodData/mods/mod-library-order.json` schema 2 分开保存手动顺序和原始导入顺序。启停、冲突应用、模型改绑、分类和名称修改不改变手动顺序；用户可将完整自动排序应用为手动顺序，也可恢复最早导入在上的基准顺序。旧 `modIds` 自动迁移且保留原手动位置。
- 原传统管理器阶段的 Nexus Slice 15 方案已并入新的 AI Slice 4：底层仍由独立 Rust service 完成搜索、授权、下载和导入桥接，但不要求先增加独立传统下载页面，传统管理器也不依赖 Agent。
- AI Agent 技术方向：只接入 DeepSeek V4，由 Rust 直接调用官方 Chat Completions、流式输出和工具调用；默认 `deepseek-v4-flash`，可切换 `deepseek-v4-pro`，不使用即将停用的旧模型别名，也不支持 OpenAI API、其它供应商或自定义地址。只读工具可自动执行，写操作只生成短时计划，用户确认后由 Rust 重新校验并复用传统 service。API Key 不写入普通 JSON，生产环境使用 Windows Credential Manager。
- AI Agent Slice 1（已完成）：设置和连接测试、悬浮窗口真实对话、流式响应、本地 MOD/冲突/术语只读工具；不执行启停、卸载、改绑或下载。
- AI Agent Slice 2（已完成）：自然语言只生成 5 分钟有效的本地操作计划；确认时重新校验状态并复用传统后台任务，支持批量启停/卸载、冲突优先级和模型改绑。
- AI Agent Slice 3（已完成实现，待手动验收）：用户主动发起后，Rust 盘点全部可部署文件，以“保留证据/排除证据”本地规则处理确定项，只把证据冲突或不足的文件组交给 DeepSeek。用户逐项确认后仍只记录部署排除并协调游戏目录文件，本地库原始文件保留，支持恢复最近批次、指定 MOD 或全部排除项。
- AI Agent Slice 4（已完成实现，待手动验收）：DeepSeek 官方联网搜索只返回经过 Rust 页面规则校验的来源；现支持 Nexus Mods、踩蘑菇、3DM、哔哩哔哩、Mod DB、GitHub 和 CurseForge，并区分 MOD 页面、视频分享和代码仓库。Nexus Personal API Key 独立保存，Premium 账户可在确认短时计划后下载并复用传统压缩包导入；其他来源只通过系统浏览器打开。
- AI Agent 五项核心规划：主动扫描全部已安装 MOD 的可清理部署文件；联网搜索候选并通过 Nexus 受控下载；自然语言批量控制传统管理能力；使用 MHW MOD 制作知识和文件解析器解释每个 MOD 的资源作用与整体工作链；使用完整、版本化的 MHW 事实和攻略知识回答查询、比较、推荐、排查与规划问题。
- AI 可选边界：普通导入和所有传统管理功能不调用、不等待也不依赖 DeepSeek。冗余清理只在用户从助手主动发起后生成待确认计划，默认保留本地 MOD 库副本，仅排除并协调游戏目录部署文件，支持恢复。
- 知识架构分为 `game-facts`、`game-guides`、`modding` 和本地 `analysis` 缓存。前三者以可选 `.acukb` 包安装到 `AcumodData/knowledge/packs/`，不进入 Acumod 主安装器；完整安装目标控制在 100 MB 内，超出时继续按知识类别拆包。
- 完整游戏知识以 Steam/PC 最终版本 `15.23` 为目标。项目确认 `15.10` 是最后一次有明显游戏内容和机制变化的更新；`15.11` 至 `15.23` 主要是修复、Steam Deck/语言适配、系统文件和宣传数据更新，没有新增怪物、武器或大型任务。因此本地 `15.10.00` 可作为 `15.23` 的内容事实基线；模型识别、EVAM 和繁中 curated 数据仍如实保留其来源版本，外部数值和再分发许可仍须独立审计。
- 知识检索采用稳定 ID/别名解析、结构化关系查询和 SQLite FTS5 全文检索；第一版不携带向量数据库、预计算向量或本地嵌入模型。DeepSeek 负责多轮检索、理解和解释，具体游戏实体、数值和解锁条件必须由知识包证据核验。
- 当前实现截点：AI Slice 1 至 Slice 4 已完成实现；Slice 5/6 已接通知识包、MOD 分析、实体/关系查询、攻略检索和回答来源展示。开发包以 Steam/PC `15.23` 为目标并以 `15.10.00` 为内容基线，当前包含 21,455 个实体、45,194 条关系、18 条 MOD 技术文档与 18 条攻略摘要；354 条任务资料中已有 329 个已核验任务链条目、180 条前置任务关系和 466 条解锁条件。活动、斗技场/挑战任务已有保守的可核验条件；特别任务与交货委托的完整链仍在制作与校验中。
