# AcuAI 知识与高风险操作验收

本文是 AcuAI 知识包和高风险 Agent 能力的人工验收入口。自动测试只能证明 DTO、校验和受控 service 的基本行为；只有本清单中的真实对话与受确认操作通过后，才能把相应能力标记为人工验收完成。

## 验收原则

- 只使用专门的测试 MOD 库和测试游戏目录，禁止把清理或下载验收直接对准用户真实游戏目录。
- DeepSeek、Nexus 凭据只通过设置页保存到系统凭据管理器；验收记录不得包含密钥、完整本地路径或下载的一次性 URL。
- 每个写操作都要记录计划摘要、确认前后状态、结果和警告。取消、过期和状态漂移同样是必测结果。
- 未通过的项目必须保留失败条件和最小复现步骤，不得以模型自然语言回答“看起来合理”替代安全验证。

## 发布前置：知识来源许可

运行下列命令，并把输出摘要记录到验收记录：

```powershell
npm.cmd run knowledge:audit-licenses
npm.cmd run knowledge:verify-release
```

`knowledge:verify-release` 必须通过，才允许将知识包作为公开下载附件发布。对每个外部来源，需在 `references/knowledge/sources/catalog.json` 中记录可复核的许可或授权依据、派生内容范围和适用游戏版本；公开可访问、链接回原站或仅保存“摘要”都不自动等于允许再分发。

当前开发包处于“仅本地开发验收”状态。任何仍为 `notAudited`、`requiresPermission`、要求发布前审计或游戏版本为 `unverified` 的来源都会阻止正式发布。

## Slice 3：冗余文件清理

### 前置条件

1. 使用至少三个专门测试 MOD：一个含已识别游戏资源，一个含确定可排除说明/备份文件，一个含需 AI 判断的纯文本文件组。
2. 测试游戏目录只包含由 Acumod 部署的副本，并为至少一个冲突路径准备两个已启用 MOD。
3. 配置可用的 DeepSeek V4 测试密钥；记录模型版本和验收日期，不记录密钥。

### 必测场景

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 只读扫描 | 在 AcuAI 发起清理扫描 | 扫描不改写 manifest、本地 MOD 库和游戏目录；结果区分本地保留、本地建议排除和 AI 审核。 |
| 隐私边界 | 请求读取候选内容 | 仅允许审查范围内的安全纯文本，单文件限制生效；二进制、图片、绝对路径和疑似凭据不进入模型上下文。 |
| 用户取消 | 生成清理审查后取消 | 不产生部署排除记录，不改动游戏目录。 |
| 确认排除 | 仅勾选低风险候选后确认 | 原始 MOD 库文件仍存在；仅部署副本按计划协调；manifest 记录排除项、理由和选择。 |
| 冲突恢复 | 排除当前冲突赢家的文件 | 游戏目录恢复剩余已启用 MOD 中优先级最高的等价文件。 |
| 恢复 | 生成并确认最近批次、指定 MOD、全部排除项恢复计划 | 只恢复记录过的排除项；状态漂移或文件内容不匹配时安全失败并给出警告。 |
| 计划保护 | 在确认前改变 MOD 状态或等待五分钟 | 执行被拒绝，不使用过期或状态漂移的计划。 |

## Slice 4：联网搜索与 Nexus 安装

### 前置条件

1. 使用独立 Nexus 测试账号；仅 Premium 账号可验证受控下载，普通账号只验证受限提示与打开页面。
2. 使用空的测试下载暂存目录、测试 MOD 库和测试游戏目录。
3. 准备一个合法 MHW Nexus MOD 页面、一个非允许域名 URL、一个无效 MOD 或文件 ID，以及一个含多候选内容根的测试归档。

### 必测场景

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 联网搜索 | 请求一个具体 MOD | 只展示 Rust 校验过的 HTTPS 具体页面；来源类型正确标记为 MOD 页面、视频/动态或代码仓库。 |
| 恶意/无效来源 | 提供首页、搜索页、伪造子域名或非白名单 URL | 不进入可安装候选，不能诱导工具调用。 |
| Nexus 鉴权 | 未配置、无效、普通会员、Premium 账号分别测试 | 错误与权限提示明确；普通会员不能下载；密钥不显示或写入 manifest。 |
| 下载计划 | Premium 账号选择具体文件 | 必须先展示短时计划并等待确认；取消、过期、状态漂移均不得下载。 |
| 下载校验 | 确认后下载 | 验证 HTTPS 来源、响应大小、实际长度和归档类型；仅在 staging 创建临时文件；失败只清理本任务创建的文件。 |
| 导入桥接 | 下载成功后继续导入 | 复用传统压缩包预览、候选分支选择、重复 MOD 和冲突检测；下载完成不自动启用 MOD。 |
| 中断恢复 | 模拟网络中断或关闭操作 | 报告失败且不留下伪完成归档、部署记录或已启用状态。 |

## 验收记录

每次人工验收应创建一条记录，至少包含：验收版本/提交、Windows 与应用版本、知识包版本、模型版本、测试账号权限级别、使用的匿名化 fixture、每个场景的结果、计划 ID 的脱敏摘要、警告与失败复现步骤。记录不得包含 API Key、Nexus 一次性 URL、真实游戏路径、用户 MOD 名称或内容。

所有 Slice 3、Slice 4 场景通过且许可严格检查通过后，才可在项目状态中把相应的“待手动验收”或“开发包”表述改为已完成/可发布。
