# AcuAI 知识与高风险操作验收

本文提供 AcuAI 知识包和高风险 Agent 能力的可重复人工回归与公开发布验收清单。自动测试只能证明 DTO、校验和受控 service 的基本行为；当前开发版本的 Slice 3/4 已依据实际使用标记为已验收，本清单不推翻该状态。后续出现问题或准备公开发布时，应使用本清单记录真实对话与受确认操作。

## 验收原则

- 只使用专门的测试 MOD 库和测试游戏目录，禁止把清理或下载验收直接对准用户真实游戏目录。
- DeepSeek 凭据只通过设置页保存到系统凭据管理器；验收记录不得包含密钥或完整本地路径。
- 每个写操作都要记录计划摘要、确认前后状态、结果和警告。取消、过期和状态漂移同样是必测结果。
- 未通过的项目必须保留失败条件和最小复现步骤，不得以模型自然语言回答“看起来合理”替代安全验证。
- 数值、掉率、配方、斩味和机制问题遵循 [knowledge-data-standard.md](knowledge-data-standard.md)：固定 `15.10.00` 最终内容基线中、已完成来源和字段校验的资料可以作为精确答案依据，并标注兼容运行版本 `15.23`；网页资料只能标为联网参考，不能伪装成已安装的本地数值库。

## 游戏与 MOD 知识问题库

完整的 30 题人工问答验收见 [knowledge-question-bank.md](knowledge-question-bank.md)。它包含 20 个游戏知识/攻略问题和 10 个 MOD 技术问题，并将“应答”“部分应答”“安全缺口”“需上下文”分开评分。执行题库时，严格按其中的前置条件、原始问题和判题锚点记录结果；无来源的精确数字、配方或文件操作建议一律判为失败。

### 资料路由必测场景

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 本地数值 | 询问已覆盖的怪物肉质或防具配方 | 模型调用本地 MHWData 工具；回答下方显示“本地数值资料”，并带 `15.10.00` / `15.23` 信息。 |
| 本地文本 | 询问配装建议或 Acumod 使用方式 | 模型查询相应攻略或帮助文本包；来源显示“本地参考资料”，不把建议说成唯一数值结论。 |
| 联网补充 | 提问本地 MHWData 未覆盖的明确机制或前置资料 | 模型先尝试本地资料，再调用 `search_game_sources`；候选只能来自 Kiranico MHW、MHWorldData 上游项目或 Monster Hunter 官方页面，来源显示“联网参考资料”。 |
| 训练知识兜底 | 在断开联网或刻意提问三类资料均未覆盖的常识性问题 | 若模型回答，相关段落必须原样包含“以下为模型训练知识，未经过本地或联网资料核验”；回答下方不得伪造本地或联网来源卡片。 |
| 本地状态 | 提问已安装 MOD 的状态或要求修改 MOD | 模型必须使用本地查询 / 计划工具，联网资料和训练知识不能替代当前工作区状态或写操作确认。 |

## 发布前置：知识来源许可

运行下列命令，并把输出摘要记录到验收记录：

```powershell
npm.cmd run knowledge:audit-licenses
npm.cmd run knowledge:verify-release
```

`knowledge:verify-release` 必须通过，才允许将知识包作为公开下载附件发布。对每个外部来源，需在 `references/knowledge/sources/catalog.json` 中记录可复核的许可或授权依据、派生内容范围和适用游戏版本；公开可访问、链接回原站或仅保存“摘要”都不自动等于允许再分发。

当前开发包处于“仅本地开发验收”状态。任何仍为 `notAudited`、`requiresPermission`、要求发布前审计或游戏版本为 `unverified` 的来源都会阻止正式发布。

## Slice 3：冗余文件清理（可选回归清单）

### 前置条件

1. 使用至少三个专门测试 MOD：一个含已识别游戏资源，一个含确定可排除说明/备份文件，一个含需 AI 判断的纯文本文件组。
2. 测试游戏目录只包含由 Acumod 部署的副本，并为至少一个冲突路径准备两个已启用 MOD。
3. 配置可用的 DeepSeek V4 测试密钥；记录模型版本和验收日期，不记录密钥。

### 必测场景

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 只读扫描 | 在 AcuAI 发起清理扫描 | 扫描不改写 manifest、本地 MOD 库和游戏目录；结果区分本地保留、本地建议排除和 AI 审核。 |
| 隐私边界 | 请求读取候选内容 | 仅允许审查范围内的安全纯文本，单文件限制生效；二进制、图片、绝对路径和疑似凭据不进入模型上下文。 |
| 用户取消 | 生成清理审查后取消 | 不产生部署排除记录，不改动游戏目录。 |
| 确认排除 | 仅勾选低风险候选后确认 | 原始 MOD 库文件仍存在；仅部署副本按计划协调；manifest 记录排除项、理由和选择。 |
| 冲突恢复 | 排除当前冲突赢家的文件 | 游戏目录恢复剩余已启用 MOD 中优先级最高的等价文件。 |
| 恢复 | 生成并确认最近批次、指定 MOD、全部排除项恢复计划 | 只恢复记录过的排除项；状态漂移或文件内容不匹配时安全失败并给出警告。 |
| 计划保护 | 在确认前改变 MOD 状态或等待五分钟 | 执行被拒绝，不使用过期或状态漂移的计划。 |

## Slice 4：联网搜索与本地导入桥接（可选回归清单）

### 前置条件

1. 使用测试 MOD 库和测试游戏目录。
2. 准备一个合法 MHW MOD 页面、一个非允许域名 URL，以及一个含多候选内容根的本地测试归档。

### 必测场景

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 联网搜索 | 请求一个具体 MOD | 只展示 Rust 校验过的 HTTPS 具体页面；来源类型正确标记为 MOD 页面、视频/动态或代码仓库。 |
| 恶意/无效来源 | 提供首页、搜索页、伪造子域名或非白名单 URL | 不进入候选，不能诱导后续工具调用。 |
| 外部打开 | 选择 Nexus、踩蘑菇、3DM、GitHub 等候选 | 明确提示在系统浏览器打开；不要求 API Key、不读取账户状态、不在应用内下载。 |
| 本地导入桥接 | 手动下载后导入测试归档 | 复用传统压缩包预览、候选分支选择、重复 MOD 和冲突检测；不会自动启用 MOD。 |

## 验收记录

每次人工验收应创建一条记录，至少包含：验收版本/提交、Windows 与应用版本、知识包版本、模型版本、使用的匿名化 fixture、每个场景的结果、计划 ID 的脱敏摘要、警告与失败复现步骤。记录不得包含 API Key、真实游戏路径、用户 MOD 名称或内容。

Slice 3、Slice 4 已在当前开发版本中依据实际使用标记为已验收。若准备公开发布知识包，仍须完成本清单中适用的回归场景并通过许可严格检查，届时才可标记为“可发布”。
