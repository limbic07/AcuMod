# MHW 最终版数值知识标准

本规范适用于 AcuAI 的游戏数值、掉落、配方、任务条件和战斗机制知识。知识包的运行兼容目标是 Steam/PC 最终版本 `15.23`，其**最终内容与数值基线固定为 `15.10.00`**。项目确认 `15.10` 是最后一个具有实际游戏内容或机制变化的更新；`15.11` 至 `15.23` 不改变本规范覆盖的怪物、装备、技能、任务和掉落数值。

## 基本结论

- 回答中的数值版本为 `15.10.00` 内容基线，兼容运行版本标为 `15.23`；两者必须同时保留，不能把来源伪装为直接来自 `15.23` 资源。
- 固定提交的 `MHWorldData` 快照是当前最终内容事实的唯一主输入。不存在因 `15.23` 未标注而必须重解包全部游戏资源的要求。
- 每项具体数值仍必须能追溯到固定数据源中的字段、行键和文件哈希，并通过结构、范围、外键和必要抽样校验。
- Wiki、论坛和攻略用于发现缺口、验证与补充攻略；它们不能替代结构化事实字段。

这项政策不通过把所有字段的来源标签直接改成 `15.23` 实现。每条事实仍如实记录 `15.10.00` 内容基线和实际来源；通过固定提交、完整性校验和抽样核对后，可以作为最终内容事实包使用。

## 数值事实准入链路

```
固定的 15.10.00 内容数据源
  -> 固定提交/发布文件、表清单与 SHA-256
  -> 确定性 ETL 与字段映射
  -> 结构、范围、外键与跨表校验
  -> 独立资料或游戏内读数的必要抽样比对
  -> 15.10 固定 MHWData 原始行数据库（兼容 15.23）
  -> Agent 的本地优先回答与来源展示
```

每个进入数值包的字段必须记录：

- `contentBaselineVersion: 15.10.00` 与 `gameVersion: 15.23`（运行兼容标记）；
- 固定来源提交/发布版本、源文件相对路径、文件 SHA-256、行键和字段名；直接解析游戏资源时额外记录解析器版本、资源类别和字段偏移；
- 实体稳定 ID、单位、数量范围、条件、概率分母与奖励槽语义；
- 独立交叉校验来源、比对日期和结论；
- 解析未知、冲突或未验证时的缺口状态。

数值数据库不保存用户游戏绝对路径、完整原始二进制或未脱敏存档；它只保存可复现的上游 CSV 行、稳定查询索引与校验元数据。

## 数据源优先级

1. **固定提交的 MHWorldData**：数值主来源。必须固定表清单、提交、每表版本与哈希；构建器直接保存原始 CSV 行并建立受控关联索引。
2. **MHW-Editor 与同键游戏文本**：用于官方简繁名称桥、字段布局和名称键复核；解析器/文本提交也必须固定记录。
3. **游戏内读数与独立结构化资料**：用于抽样核对、发现冲突和补齐上游明确缺失的领域。MHWorldData 的采集、特殊物品解锁和武器动作值缺口不能因其为主输入而被忽略。
4. **官方资料与攻略书**：用于验证难以直接结构化的公式、调查任务生成机制和状态机制；必须记录样本、版本与复核结果。
5. **Wiki、论坛、视频和攻略页面**：只能生成待核验线索或攻略资料，不能替代数值事实字段。

## 各类数据的最低验收要求

| 数据域 | 主资源/字段 | 最低校验 |
| --- | --- | --- |
| 武器 | 每阶段攻击、属性/异常、会心、斩味段、孔位、专属参数、升级材料 | 与游戏内面板抽样、武器树外键、斩味总长度和值域。 |
| 防具 | 防御、耐性、孔位、技能、套装、制作与升级材料、解锁 | 每套五部位完整性、材料数量、技能等级和游戏内抽样。 |
| 技能与机制 | 每级效果、触发阈值、持续时间、冷却、公式参数 | 固定输入的可重复游戏内实验或独立公式资料双重核对。 |
| 怪物 | 形态、部位、软化/破坏/怒状态肉质、异常与部位耐久 | 状态互斥性、部位完整性、与猎人笔记/实测抽样。 |
| 掉落 | 剥取、捕获、断尾、破坏、掉落物、任务、调查、聚魔、活动奖励 | 每条有来源类别、条件、数量、概率；所有概率按奖励组而非单独页面文本建模。 |
| 调查任务 | 危险度、目标数量、奖励槽类别、箱位颜色、奖励组、物品、数量和概率 | 明确区分铜/银/金/紫等实际奖励槽语义、普通与历战规则、多目标分配和素材类别。 |
| 任务与进度 | 任务、前置、开放条件、奖励、活动限制、交货委托 | 关系两端均为稳定 ID；特别任务和同名任务必须人工复核。 |

## Agent 回答规则

- 任何“多少、概率、掉率、材料数量、斩味格数、伤害、阈值、持续时间、哪一个更高”问题必须走数值事实查询或确定性计算器。
- 没有 `15.10.00` 内容基线的已核验字段时，AcuAI 优先说明该本地缺口并查询受白名单限制的资料页。联网结果必须标为“联网参考”；两者均不足时可给出模型训练知识，但必须逐段标明“以下为模型训练知识，未经过本地或联网资料核验”，不得把它写成确定数值或已验证机制。
- 调查任务“金/银奖励掉什么”必须列出所依据的目标、等级、奖励槽、奖励组和概率条件；不能只回答“金色更容易出稀有素材”。
- 建议、经验和攻略与确定数值分开输出；推荐不是事实，必须标明前提。

## 迁移顺序

1. 固定 `15.10.00` 数据源提交、表清单与哈希，并写入 `15.10.00` 内容基线和 `15.23` 运行兼容标记。
2. 先完整导入怪物掉落/调查奖励、武器面板与斩味、装备配方/套装效果和技能等级四类高频数值。
3. 为每类建立结构化 schema、范围/外键/概率校验和必要抽样报告。
4. 用通过校验的最终内容字段补充固定数据库；只保留来源确实缺失的字段作为缺口，不能把推断结果写成行数据。
5. 将 `docs/knowledge-question-bank.md` 中的缺口题转为 `15.10.00` 内容基线回归题，并逐题执行真实 AcuAI 验收。
