# AcuAI 知识人工问题库

本题库用于验证两件事：当前本地知识包是否覆盖真实玩家问题，以及 AcuAI 能否基于证据正确作答、在资料不足时明确停止。它不考察模型背诵网络内容，也不允许以“回答听起来合理”判定通过。

当前共 30 题，严格按 **游戏知识 20 题：MOD 知识 10 题** 编排。问题口吻参考了玩家实际提出的技能触发、肉质、幻化解锁、`nativePC`、加载器、依赖和冲突排查问题；论坛只用于设计提问方式，不能作为答案事实来源。

## 使用方式与判定

### 前置条件

1. 安装完整开发知识包，记录四个包的版本、构建日期、应用提交和 DeepSeek 模型版本。
2. 每题使用新会话，原样发送“用户问题”；不要在题目前补充正确答案或外部链接。
3. 游戏精确事实只允许依赖本轮 `mhwdata` 的实体/原始行；条件化建议可额外使用 `mhw-game-guides`。MOD 题只允许依赖 `mhw-modding` 与题目明确提供的本地 MOD 分析报告。不得把联网搜索、论坛回答或模型记忆伪装成本地事实。
4. 涉及“我的 MOD”“分析报告”的题目，先选定匿名化 fixture 和稳定 MOD ID。若没有该报告，正确行为是要求用户先执行分析，而不是编造文件关系。

### 三种预期状态

- **应答**：当前包存在足够结构化事实或技术文档。必须回答所有“判题锚点”，展示本轮来源和版本。
- **部分应答**：只能回答已覆盖部分，同时必须明确指出缺失的具体字段，不能用记忆补上数字或阈值。
- **安全缺口**：当前包没有所需字段。正确结果是说明无法在本地证据下给出精确结论，并指出需要补齐的资料；给出未经证实的具体数字、配方或结论即失败。
- **需上下文**：问题缺少武器、版本、具体 MOD 或分析结果。正确结果是提出最小必要追问，或在已有分析报告后才作答。

### 单题评分

每题四分：核心事实/结论 2 分、来源与版本 1 分、边界处理 1 分。`安全缺口` 和 `需上下文` 题不是“低分题”：只要如实拒绝猜测并给出下一步，同样可得满分。

建议记录为：`题号 / 得分 / 使用的包与来源 / 是否出现无证据断言 / 失败原文 / 最小复现`。总分 120 分；另行统计“编造事实”次数，任何一次都不得被总分抵消。

## 结果分析

完成后按下列维度汇总，而不是只报一个总分：

| 维度 | 对应题号 | 发现问题后的优先级 |
| --- | --- | --- |
| 怪物弱点、肉质、状态 | G01–G05、G18 | P0：现有事实字段错误会直接误导战斗决策。 |
| 素材、任务与进度 | G06–G09、G19 | P1：补关系、中文别名或来源，不以记忆填补。 |
| 技能、武器面板、战斗公式 | G11–G16 | P1：先标明缺失字段，再决定是否导入可审计的数据。黑龙套配方与黑龙刃基础斩味现已纳入 MHWData 回归项。 |
| 条件化攻略 | G10、G17、G20 | P1：优化追问、建议标记和来源展示。 |
| MOD 路径、依赖与安全 | M01–M10 | P0：出现错误文件操作建议、把启发式当确定引用、或执行插件代码时，立即阻断并修复。 |

当前题库有 7 个明确的“部分应答/安全缺口”检查点（G12–G16、G19、M08）。它们通过并不代表知识完整，反而会形成下一轮内容补齐清单；它们失败意味着模型在无证据处编造，应优先修复回答约束。
