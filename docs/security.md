# 安全边界

Acumod 会操作游戏目录和用户下载的 MOD 文件，因此文件安全是核心设计约束。后续 AI Agent 也必须遵守同一套边界。

## 基本原则

- 默认不删除用户文件。
- 默认不覆盖文件，除非用户看到预览并确认。
- 只在用户确认的 MHW 游戏目录、应用配置目录、软件数据目录和缓存目录内操作。
- 文件操作由 Rust service 统一执行，前端和 AI Agent 不直接操作文件系统。
- 危险操作必须能说明“会改哪些文件、为什么改、是否不可逆”。
- Acumod 只删除自己记录过的部署文件；禁用 MOD 删除的是游戏目录中的部署副本，不删除软件 MOD 库中的原始副本。

## 路径安全

处理路径时建议：

- 对用户输入路径进行规范化和存在性检查。
- 确认目标路径位于已授权的游戏目录或应用管理目录内。
- 避免通过 `..`、符号链接或快捷方式跳出授权目录。
- 对删除、覆盖、移动操作使用操作计划预览。
- 不对未知路径执行递归删除。
- 禁用和卸载时只处理 Acumod 元数据中记录过的文件路径。

后续实现文件操作前，应先建立统一的路径校验函数，避免每个 command 自己判断。

## 存储位置边界

`AppData` 只用于保存小配置，例如 `config.json` 和用户设置。MOD 库和导入暂存放在软件目录旁的 `AcumodData/` 下，便于用户理解和迁移，也避免把大体积 MOD 文件塞进系统应用数据目录。

如果后续安装包默认安装到 `Program Files` 这类普通用户不可写目录，软件目录内写入可能失败。发布前需要选择用户可写安装目录，或提供 MOD 库位置设置。

## 复制式部署安全

当前确认的 MOD 部署方式是复制：

- 安装：复制或解包到 Acumod 软件 MOD 库。
- 启用：从软件 MOD 库复制到 MHW 游戏目录。
- 禁用：删除 MHW 游戏目录中的已部署副本。
- 卸载：删除软件 MOD 库中的 MOD 副本，并清理该 MOD 仍然部署在游戏目录中的文件。

因此，每次启用必须记录写入了哪些 `deployed_path`。禁用和卸载必须依据记录删除，不能仅根据文件名、目录名或 MOD 名称猜测删除范围。

如果启用时目标路径已经存在，应先判断该文件是否由 Acumod 管理：

- 如果目标文件由同一个 MOD 管理，可以覆盖或刷新部署。
- 如果目标文件由另一个 MOD 管理，应生成冲突提示。
- 如果目标文件不是 Acumod 管理的文件，应提示用户确认；确认后允许覆盖，不额外创建备份。

当前启停、卸载、一键还原和冲突排序切片已经实现部署记录驱动的复制和删除：启用时把实际部署路径写入 MOD manifest 的 `deployedFiles`；禁用时只删除这些记录中的文件，并向上清理由这些文件留下的空目录；卸载时先清理该 MOD 的已记录部署文件，再删除 Acumod 本地库中的该 MOD 目录；一键还原时清理所有 manifest 中记录过的部署文件，并把相关 MOD 标记为未启用；应用冲突组时遍历组内全部冲突文件，按整体 MOD 顺序复制最终版本并更新部署记录归属。目标已存在但未被 Acumod 记录时仍会要求用户确认覆盖。

Acumod 只维护一套当前部署状态：每个 manifest 的 `enabled` 与 `deployedFiles` 表示当前游戏目录状态，`conflict-orders.json` 保存冲突组顺序。

多配置移除的迁移不包含任何自动文件清理：旧版本留下的 `profiles.json` 不再读取、写入或自动删除，避免程序擅自处理用户已有数据。升级后仍应以 manifest 和 `conflict-orders.json` 判断当前状态；用户若自行清理旧快照，需先退出 Acumod 并自行备份，且不得删除 `installed/` 下的 manifest 或冲突顺序文件。

当组内 MOD 被启用、禁用或卸载时，Acumod 会重新应用它所在的冲突组，让顺序中的下一个适用且已启用 MOD 接管相关文件；若目标无法安全覆盖，会在操作结果中记录警告而不绕过确认机制。

## 压缩包导入安全

当前压缩包导入通过随 Acumod 打包的 7-Zip 解包组件处理 `.zip`、`.7z`、`.rar`。解包目标只允许位于 `AcumodData/mods/staging/imports/` 下，解包后仍然必须通过同一套 MOD 内容根识别规则，不能因为来源是压缩包就绕过预览、manifest 记录或本地 MOD 库安装流程。

随包分发 7-Zip 时必须保留对应许可文件。RAR 解压相关代码带有 unRAR restriction，因此 Acumod 只使用它解压用户提供的 RAR 文件，不提供创建 RAR 压缩包的能力。

压缩包导入阶段不直接写入 MHW 游戏目录。后续如果加入自动清理 staging，需要只删除 Acumod 自己创建并记录的 staging 子目录，不能对用户下载目录或任意压缩包来源目录执行删除。

## 外部管理器导入安全

狩技 MOD 盒子导入把外部目录当作只读来源：只接受其根目录下 `Mods_582010/<数字模块 ID>/info.xml` 与 `files/`，忽略 `Backup_582010`、下载、存档和临时目录。扫描时跳过符号链接，并校验模块目录和 `files/` 目录始终位于用户选择的盒子目录范围内。

扫描会读取盒子 `config.ini` 中记录的游戏路径，并逐块比较文件内容；该比较不复制、不覆盖、不删除任何游戏或盒子文件。单个文件匹配不能建立唯一归属，因为多个 MOD 可能提供同路径、同内容文件；状态同步必须先建立全部本地 MOD 的路径和内容关系。

用户选择导入时，Acumod 只复制 `files/` 到自己的本地库，并复用普通导入的路径校验、重复内容识别和临时目录清理规则。导入完成后的状态同步只修改 Acumod 元数据：完全匹配记为已启用；部分匹配只有在所有差异都能由已启用冲突提供者解释、且整体优先级无环时才记为已启用并纳入冲突顺序；其余情况统一记为未启用。

自动状态同步不需要用户确认，因为它不写游戏目录。由检测建立的部署记录必须标记为“观察所得”，与 Acumod 主动复制产生的记录区分。禁用、卸载和一键还原准备删除观察所得文件前，必须确认目标仍与记录时的有效本地内容一致，并确认没有其他已启用等价提供者需要该文件；任一条件不满足时保留文件并给出警告。

状态同步不得把不确定性转嫁为逐文件确认。无法解释的部分匹配、完全无匹配和混合覆盖统一按未启用处理；无法确定归属的文件默认不纳入删除范围。只有用户随后主动执行会覆盖未知游戏文件的部署或冲突修复操作时，才使用一次汇总确认。

## 操作计划

安装、启停、卸载、模型改绑、调整冲突排序、一键还原、AI 执行动作都建议先生成 `OperationPlan`，再执行。

一个操作计划至少应包含：

- 操作类型：安装、启用、禁用、卸载、模型改绑、调整冲突排序、一键还原等。
- 将影响的文件列表。
- 是否会覆盖已有文件。
- 是否会删除文件。
- 是否不可逆。
- 风险提示。
- 对模型改绑，计划必须同时展示原始目标、选择目标、变化后的部署路径、MRL3 修正数量、EVAM 绑定修正数量和校验警告。

前端展示计划后，由用户确认。Rust service 收到确认后再执行。

## 覆盖和恢复

Acumod 不额外备份游戏目录中被覆盖的文件。各 MOD 的原始副本保存在本地 MOD 库中；用户可通过调整冲突组顺序并重新应用，恢复任一已安装 MOD 的版本。

如果被覆盖文件不是 Acumod 管理的 MOD 文件，用户确认覆盖后无法由 Acumod 自动恢复。界面必须在执行前明确提示这一点。

## 模型替换与改绑安全

识别结果本身不是可执行计划。Slice 14 只允许五类经过验证的资源改绑，并把路径生成和文件内容修正限制在独立 service 中。

建议规则：

- 文件 ID 表必须能区分模型类型和子类型。
- 如果无法识别 MOD 的模型类型，应标记为未知。
- 同一个 MOD 可能替换多个模型，识别结果需要逐项展示。
- 只允许武器、防具、随从防具、投射器/飞翔爪和玩家发型改绑；人物语音只识别，不提供改绑。
- 已启用 MOD 不允许修改改绑选择，必须先按部署记录禁用。
- 原始 MOD 库文件永不改写；manifest 只记录目标选择，变换后的内容只在部署时写入游戏目录。
- 目录、文件名和 MRL3 资源路径必须从同一个有效部署计划产生；禁止各链路自行猜测。
- MRL3 只修改贴图表中精确命中的路径，必须校验文件头、表范围、字符串长度和目标碰撞；不解析或改写 `.nbnk`。
- `.evam` 只接受已识别防具手臂路径、26 字节长度、`EVAM` 标记和版本 3；改绑时源 ID 必须与识别结果一致，否则阻止部署。
- 预览和应用使用同一组校验；应用时必须重新计算，不能直接信任前端返回的路径。

## Tauri 权限

当前 `src-tauri/capabilities/default.json` 只启用了：

- `core:default`
- `opener:default`

后续新增文件选择、文件系统访问、网络下载等能力时，应只添加当前功能所需的最小权限。不要为了方便一次性打开宽泛权限。

当前 `tauri.conf.json` 中 `csp` 为 `null`，适合早期开发阶段。进入更接近发布的阶段前，应确认是否需要收紧 CSP。

## AI Agent 安全边界

AI Agent 只能提出受控查询或操作请求，不能直接执行文件操作。模型输出、联网搜索结果、MOD 页面说明和压缩包内文本全部视为不可信输入。

允许：

- 解释用户意图。
- 查询已有 MOD 状态。
- 查询本地 MHWData、MOD 技术和软件说明资料；游戏攻略类问题按需使用受控联网来源。
- 联网搜索 MOD 并提供候选来源链接。
- 生成操作建议。
- 生成待确认的操作计划。
- 在用户确认后调用传统管理器已有能力。
- 主动盘点已安装 MOD 的全部可部署文件，先用本地确定性规则分流，再对模糊文件调用 AI 审核，并在确认后调用部署 service 清理游戏目录副本。
- 查询带来源和版本的 MOD 知识与游戏数据；游戏攻略类内容只通过当轮受控联网资料补充。

不允许：

- 直接删除、覆盖、移动文件。
- 绕过用户确认执行危险操作。
- 绕过 Rust service 自己拼路径。
- 执行传统 UI 尚未支持的隐藏能力。
- 在未确认来源、文件和规则前自动下载并安装 MOD。
- 调用需要账号、token、会员或站内下载参数的第三方下载 API。
- 把 AI 翻译结果当成确定事实覆盖原始 MOD 名称。
- 把模型返回的工具名、参数、路径或 URL 当成已经校验的命令。
- 向模型提供 API Key、本地绝对路径、完整文件清单、二进制内容、图片内容或无关操作日志。
- 允许网页、MOD 说明或压缩包内文本改变 system prompt、工具权限和确认规则。
- 以“清理”为由删除 Acumod 本地 MOD 库的原始副本，或在没有部署排除记录时直接删除游戏目录文件。
- 把模型训练知识当成已核验的文件用途、冲突结论、素材数值、解锁条件或配装事实，或省略其未核验标记。

AI Agent 的权限应低于或等于传统 UI。任何 AI 动作都必须能映射到明确的传统管理器操作。

### 工具和计划校验

- 工具由 Rust 枚举和固定 registry 声明，参数使用严格 JSON Schema，并拒绝未知字段。
- 只读工具只返回满足当前问题所需的精简 DTO，并限制结果数量。
- 写工具只能创建待确认计划，不能在模型工具循环中执行实际写入。
- 计划使用不透明 `planId`、当前状态版本和 5 分钟过期时间；只保存在 Rust 内存，不把完整执行参数交给前端修改。
- 用户确认时重新读取当前状态并调用既有预览 service；状态漂移、目标不存在、计划过期或校验失败时拒绝执行。
- 禁止提供通用命令、任意 Tauri command、任意路径、shell、脚本、网页自动操作和直接下载 URL 工具。
- 冗余文件计划必须逐项保存 MOD ID、相对路径、判断理由和用户选择；执行时重新确认文件仍属于该 MOD 的有效部署记录。
- 本地清理规则必须分别记录保留证据和排除证据；两类证据同时存在或均不存在时不得由规则强行决定，必须进入 AI 审核或人工确认。
- 单独的扩展名、目录名或文件名不能决定排除。`副本`、`Copy` 等弱特征只有在规范同名文件存在、内容一致且没有运行资源证据时，才能形成确定的本地排除建议。
- 本地规则和审查快照必须带版本号；当前快照只在一次运行期间按 `auditId` 复用，关闭程序后失效，不把旧 AcuAI 结论跨运行直接套用到变化后的文件。
- 清理冲突路径必须重新协调剩余已启用所有者，不能简单删除当前游戏文件；恢复排除项也必须走相同部署计划。
- 当前实现把排除项保存到 manifest schema 17 的 `deploymentExclusions[]`。启用、禁用、冲突应用、模型改绑和快照统一从“有效部署文件”入口过滤这些路径，避免清理后被下一次操作重新复制。
- 应用清理只移除与该 MOD `deployedFiles` 记录匹配的游戏目录文件，并调用既有冲突版本恢复逻辑；恢复最近批次、指定 MOD 或全部排除项同样先生成短时计划并要求确认。
- 知识检索结果携带来源、版本和内容哈希；检索文本永远作为引用资料，不能提升为系统指令或直接形成写操作参数。
- 文本 `.acukb` 使用固定 schema；固定 `.acumhwdb` 使用仅含 MHWorldData 源行、实体别名和关联索引的专用 schema。两类文件都禁止脚本、动态库、任意 SQL、HTML 执行内容、模型提示模板和其它可执行内容。
- 知识资料先复制到受控 staging 并计算整文件 SHA-256，再校验 4 GB 上限、应用标识、manifest、schema、SQLite `integrity_check`、必要数据表和未知 trigger/view。数值库额外校验活动指针仅指向安全文件名；运行时使用只读连接、`query_only`、`trusted_schema = OFF` 和固定参数化 SQL。启用新版本失败不能破坏旧版本。
- `modding` 规则即使来自官方知识包，也只能进入 Rust 支持的固定声明式匹配器；规则不得拼接本地绝对路径、执行正则拒绝服务、调用命令或改变 Agent 权限。
- Rust 根据当前 turn 实际工具结果生成来源账本与展示卡片，模型不能自行声明为“本地已验证”。`mhwdata` 原始行标为本地数值资料，文本包标为本地参考资料，本地 MOD 分析标为本地文件分析，网页仅标为联网参考；模型训练知识不产生伪造来源卡片，且必须由模型在正文中显式说明未核验。

### 密钥和网络

- DeepSeek 凭据只由 Rust 读取，前端只能知道“已配置/未配置”和脱敏标识。
- 生产凭据保存到 Windows Credential Manager；普通配置只保存 DeepSeek V4 模型和超时等非敏感项。
- 开发环境可以从进程环境变量读取凭据，但不得打印到日志、错误详情或构建产物。
- 模型请求只允许访问 `https://api.deepseek.com`；不提供自定义 Base URL。
- 联网搜索使用 DeepSeek 官方服务端搜索，但候选页面仍必须经过 Rust 的 HTTPS、精确域名和具体内容路径校验；网页正文永远不能改变工具权限或计划参数。MOD 搜索与游戏资料搜索使用不同白名单：游戏资料仅允许 Kiranico MHW、`gatheringhallstudios/MHWorldData` 与 Monster Hunter 官方页面。来源链接只由系统浏览器打开，Acumod 不读取登录 Cookie、不模拟关注或私信，也不自动跟随页面中的网盘和短链接。
- 浏览器下载会话必须由用户选择单一目录后启动，只观察会话开始后出现的 ZIP、7Z、RAR。后端在每次轮询重新确认目录边界，拒绝符号链接、目录外路径和未完成下载扩展名；连续两次文件大小与修改时间稳定后才通知前端。通知不等于导入，用户必须再次点击确认，归档仍走既有校验与导入预览。
- 所有请求设置连接、响应和总超时，限制响应体大小，并把服务端错误转换为不含密钥的中文错误。
- 普通模型对话和只读搜索不持有文件任务锁；用户下载完成后的本地导入仍通过传统后台任务串行执行。

### 隐私和上下文

- 默认不发送游戏目录、Acumod 安装目录、用户目录或 MOD 本地来源路径。
- 默认只发送 MOD 稳定 ID、显示名、分类、启用状态、替换摘要和冲突数量；具体冲突路径只在用户明确询问且确有必要时发送相对路径。
- 不上传 MOD 压缩包、二进制文件或完整 manifest。
- MOD 技术分析先在本地读取路径、文件头、资源 ID 和内部引用，只把精简结构化证据及命中的技术资料发送给 DeepSeek；本地绝对路径和二进制内容不进入模型上下文。
- 冗余扫描只把本地规则无法确定的文件组发送给模型，内容限于相对路径、扩展名、大小、部署状态、规则证据和同目录摘要。需要补充内容时必须先确认是安全纯文本，单文件最多读取 32 KB，并在本地裁剪敏感路径、凭据形态和无关内容。
- 游戏知识回答区分 `mhwdata` 原始结构化数值、联网参考和未核验训练知识；本地数值与联网摘录均保留来源元数据。无本地资料时只能使用受控联网工具，不能任意访问网页；无联网资料时的训练知识必须在正文中明确标为未核验。
- 第一版不持久化聊天记录；关闭程序即清除当前会话。将来增加历史记录时必须提供清空入口和明确保存位置。
- 日志只记录请求阶段、耗时、DeepSeek V4 模型、工具名和成功/失败，不记录用户完整消息、模型完整回答、工具参数或凭据。

外部来源功能只展示 MOD 来源链接、来源类型和浏览器打开提示；用户手动下载后，再在传统导入流程中核对文件、识别结果和可能影响的游戏目录文件。
