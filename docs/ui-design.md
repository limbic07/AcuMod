# UI 设计

## 目标

Acumod 是面向持续管理 MOD 的桌面工具。界面优先让用户快速确认游戏状态、定位 MOD、完成导入和处理冲突；不做营销式首页，也不把高风险操作藏在抽象入口中。

本次 UI 架构切片只重组已有功能，不改变 Rust command、DTO、导入规则、部署规则或确认流程。

## 信息架构

```text
应用外壳
  ├─ 侧边导航
  │   ├─ MOD 库
  │   ├─ 导入 MOD
  │   ├─ 冲突管理
  │   └─ 设置
  ├─ 顶部状态区
  ├─ 全局任务条
  ├─ 右侧内容区（当前页面）
  │   ├─ MOD 库：已安装列表、启停、卸载、还原和操作结果
  │   ├─ 导入 MOD：文件夹或压缩包识别、候选分支、狩技 MOD 盒子扫描和导入结果
  │   └─ 设置：游戏目录、游戏文本语言和应用信息
  └─ AcuAI 悬浮助手：后续能力的独立窗口层
```

MOD 库、导入 MOD、冲突管理和设置在侧边导航中同级，使用同一个 `WorkspaceView` 页面选择状态。选择其中任意一项时，只替换右侧内容区中的当前页面，左侧导航和顶部状态区始终保留；用户可以直接从侧栏切换到任意其它页面。冲突管理页面专门展示已启用 MOD 的冲突组和组内覆盖顺序，未启用 MOD 的冲突不应进入该页面。

## 组件边界

- `AppSidebar`：展示应用名称、工作区导航、冲突数量和游戏目录状态；MOD 库、导入、冲突管理和设置统一发出 `WorkspaceView` 页面切换事件。
- `AppTopbar`：展示当前工作区标题、MOD 统计和刷新入口，不持有业务数据。
- `OperationStatusBar`：监听当前后台任务，展示任务标题、阶段、文件级进度、当前项和已耗时；不提供取消或暂停入口。
- `FloatingAgentPanel`：独立的悬浮窗口和最小化入口。承载真实对话、只读工具状态和 Slice 2 的待确认计划卡片；组件只提交 `planId` 并展示结果，不持有文件操作实现或可修改的执行参数。
- `ModLibraryToolbar`：负责 MOD 搜索、筛选、浏览排序和分类管理入口；只发出 UI 事件，不直接调用 Tauri。
- `ModLibraryTable`：负责启用状态、列表序号、名称、分类、替换信息、备注和图标操作；只接收已排序 DTO，并发出行内编辑、分类选择、拖拽排序、启停、打开目录、展开详情、模型改绑和卸载事件。
- `App.vue`：仍作为当前阶段的业务协调层，保存跨页面状态并通过 `src/api/*` 调用 Tauri；后续页面继续增长时再迁移到 `src/views/`。

## AcuAI 悬浮窗口边界

AcuAI 不会占用主导航中的一个页面，而是始终可从右下角打开的悬浮窗口。这样它可以辅助任何当前任务，但不会抢占 MOD 管理的主工作流。

接入 AI 后，窗口只能：

1. 读取已经由前端取得的展示数据，或请求 Rust 返回受控的查询 DTO。
2. 将自然语言意图转换为现有操作的受控请求。
3. 等待 Rust service 生成 `OperationPlan`，在主界面或窗口中展示计划、影响范围和风险。
4. 只有在用户明确确认后，调用既有的执行 command。

AI 不能直接操作游戏目录、本地 MOD 库或网络下载文件；传统 UI 尚不支持的功能，AI 也不能绕过实现。

悬浮窗口使用三种主要状态：

- 收起：右下角保留一个固定尺寸的 AI 图标按钮，不显示未读营销提示。
- 对话：显示当前会话消息、输入框、发送按钮和简短工具状态，例如“正在查询本地 MOD”；流式文本不能导致窗口尺寸跳动。
- 待确认计划：在对话中直接展示操作摘要、目标 MOD、警告和“确认执行/取消”按钮，不弹 WebView 原生确认框。

AcuAI 当前提供“扫描可清理文件”和“恢复最近清理”快捷入口，并已能按自然语言搜索 MOD 来源；“分析 MOD/报错”和“询问游戏知识”随 Slice 5、Slice 6 加入。快捷入口只发起对应 Agent 意图，不在前端实现业务逻辑；没有配置 DeepSeek 时仍只显示前往设置，不影响主界面工作流。

交互约定：

- 默认宽度约 `760px`、高度约 `780px`，并受应用窗口尺寸约束；窄窗口切换为贴底面板，不能遮挡应用内确认对话框和全局任务条。
- 操作计划卡片跟随生成它的 AI 回复保留在对话时间线中；完成任务 A 后继续任务 B 时，任务 A 不得被重新移动到整个对话末尾。
- 只读工具过程使用一行可折叠状态，不展示 JSON、函数名、token 数或模型推理过程。
- 流式回答阶段先展示纯文本，回答完成后只执行一次 Markdown 渲染；解析器随 AI 窗口代码加载，禁用原始 HTML 和远程图片，外部 HTTP(S) 链接交给系统浏览器打开。表格保持原生 table 布局，使表头与内容共享列宽，超宽内容由消息区域横向滚动。渲染失败必须显示错误，不能静默退回带 Markdown 符号的文本。
- 写操作计划必须使用明确中文命令名称，例如“启用 3 个 MOD”，不能只显示“执行工具”。
- 冗余文件扫描使用全局进度条显示已盘点文件数、总数和当前 MOD。结果跟随生成它的 AcuAI 回复按 MOD 分组，只显示“建议清理”或“需要确认”的项目；建议保留项仅计入扫描统计，不显示为冗长列表。每项展示判断来源、风险、理由、可信度、大小和当前部署状态。整行可点击勾选，右侧文件夹按钮可打开候选在本地 MOD 库中的所在目录；只有低风险的本地确定性建议默认勾选，AcuAI 判断的模糊项默认不勾选。生成计划时必须说明本地库原始文件会保留；恢复最近批次、指定 MOD 或全部排除项继续通过对话生成确认计划。
- 联网搜索结果使用来源、标题、作者、摘要和操作入口组成的候选列表；点击允许来源链接时可选择下载目录并显示“正在等待浏览器下载”。发现完成归档后显示文件名、大小、来源与“导入此文件”按钮；用户未点击该按钮前不导入。所有站内登录与下载继续在系统浏览器中完成。
- MOD 分析使用结构化报告展示整体工作链、组件和未知项，并可展开逐文件查看作用、替换目标、依赖、证据与可信度；同类文件可在摘要中分组，但详情不能丢失单个文件。
- 游戏问答通过 `knowledgeAnswerReady` 展示经过 Rust 核验的 Markdown、游戏事实/攻略建议标识、可展开来源、游戏版本和知识包版本。开放式问题只在关键条件影响答案时追问，不把建议伪装成唯一正确答案。
- 计划确认后，悬浮窗口显示与全局任务条一致的执行状态；文件级进度仍由全局任务条负责，避免两套进度源。
- 网络错误、未配置 Key、限流和计划过期使用窗口内中文错误及重试入口，不调用 `window.alert()`。
- “清空对话”只清除当前内存会话，不影响待执行以外的 MOD 状态。

设置页包含“AcuAI”区块：服务固定为 DeepSeek V4，只提供 `V4 Pro` 和 `V4 Flash` 模型选择、保存或删除访问密钥、测试连接。访问密钥输入框只用于提交给 Rust，保存后前端不回读明文；设置页只显示是否已配置和末尾脱敏信息。不提供供应商或 Base URL 输入，避免把密钥发送到未知服务。

Slice 5 已增加“知识库”区块，按包展示名称、知识域、版本、适用游戏版本、实体/文档/来源数量、安装大小和健康状态，并提供本地路径导入、刷新和界面内二次确认删除。检查更新、打开知识目录和在线下载在正式发布包来源确定后补充。知识包缺失时 AcuAI 明确指出缺少资料；知识包管理失败、被删除或未启用不能影响 MOD 库、导入、启停和冲突管理。

## 视觉与交互规则

- 使用 `188px` 固定侧栏和可滚动工作区，保持列表和文件路径在长内容下稳定可扫描；默认窗口为 `1440 x 820`，最小窗口为 `1100 x 680`。
- 页面区块使用克制的边框和小圆角，避免把整个页面切成漂浮卡片。
- MOD 库使用表格展示启用按钮、序号、名称、分类、替换信息、备注和操作；序号使用独立固定列。文件数、部署根目录等实现细节不作为主列表列。
- MOD 库顶部提供搜索、筛选、排序和分类管理入口；导入顺序、名称、分类和替换信息均可切换升序或倒序，并可通过“应用排序”写为新的手动顺序。“恢复导入顺序”恢复最早导入在上的基准顺序。“手动排序”显示序号列的拖拽把手并持久化浏览顺序，不显示方向切换，当前只有一套启用状态与冲突组顺序，不提供配置切换。
- MOD 库页面使用完整可用宽度，不再套用带外边距、圆角和阴影的页面卡片；检索控制区保留必要内边距，批量工具条和表格左右边缘直接贴合内容区边界。
- 分类、状态、冲突和替换目标检索只改变浏览结果；MOD 库手动排序也绝不改变冲突组覆盖顺序。
- MOD 行内操作使用带悬浮提示的图标按钮；危险操作继续由 Rust 在执行前生成内部计划，前端只在需要时显示简洁确认，不常驻展示计划和结果面板。
- 需要确认的操作使用应用内对话框，禁止使用 `window.confirm()`、`window.alert()` 等 WebView 原生弹窗，避免开发地址或浏览器来源文字进入用户界面。确认框标题、正文、风险说明和按钮均使用简体中文；删除、卸载和一键还原使用危险色确认按钮。禁用直接执行；单项启用仅在与当前已启用 MOD 存在文件冲突时确认。
- 全局任务条位于顶部状态区下方，使用整行状态带而非浮动卡片；无确定总数时只展示阶段和当前项，文件总数确定后显示进度条与完成数。任务结束后短暂保留结果再收起。
- 窄窗口下侧栏转为顶部横向导航，右侧内容区保持单列；悬浮 AI 窗口缩小但不遮挡主要确认对话框。
- 本软件面向简体中文用户，游戏内物品、模型和术语优先显示官方简体中文名称；原始 ID 和路径作为辅助信息保留。

## 狩技 MOD 盒子导入与状态界面

导入页的“从狩技 MOD 盒子导入”区块位于常规文件夹和压缩包导入之后：

- 输入盒子根目录并扫描后，以可滚动表格显示名称、盒子记录状态、初步文件比对结果和安装文件规模；“导入”列默认勾选全部模块并提供全选和清空操作。
- 点击行可在下方查看该 MOD 的安装文件路径和大小；大量文件只先显示前 80 项，并明确显示总数。
- 导入完成后自动运行游戏目录状态同步，通过全局任务条展示扫描和逐文件比对进度；用户也可点击“检测游戏实际状态”重新比较。界面不再出现接管列、接管预检和接管确认。
- MOD 库启用按钮仍只显示开启或关闭。因冲突而部分覆盖时，在名称旁显示现有冲突提示图标，悬浮提示“已启用，部分文件被更高优先级 MOD 覆盖”；不增加新的状态列。
- 状态同步结束只展示一次简短结果：已启用数量、其中部分被覆盖数量、未启用数量，以及无法还原为整体优先级的混合冲突组数量。混合冲突 MOD 按未启用显示，用户可在冲突管理中查看详情并按正常启用流程重新部署。

## MOD 库表格

MOD 库表格优先支持快速扫描、直接整理和安全启停。默认列从左到右固定为：

| 列 | 展示内容 | 交互规则 |
| --- | --- | --- |
| 启用 | 一个固定尺寸的状态图标按钮 | 已启用使用绿色实心状态，未启用使用中性描边状态；按钮放在最左列，只使用图标和悬浮提示表达状态与动作 |
| 选择 | 批量选择复选框 | 位于启用列之后；表头复选框只全选当前筛选结果，筛选变化后不保留已隐藏项目 |
| 序号 | 当前浏览顺序 | 使用独立固定列；手动排序时显示六点拖拽把手，筛选或浏览排序后按当前显示结果重新编号 |
| 名称 | 用户设置的 MOD 名称 | 单击名称后直接在单元格内编辑；原始导入名称只在详情中展示 |
| 分类 | 零个或多个分类标签 | 单击分类单元格打开多选菜单，可增删任意分类、清空分类或新建分类；子分类显示为“父分类·子分类”，不显示“自动”前缀或区分分类来源 |
| 替换信息 | 最重要的识别结果摘要，也是模型改绑入口 | 最多展示两行；其它结果合并显示为 `+N`。存在可改绑目标时整个单元格可点击并常驻改绑图标；已启用 MOD 可查看但不能修改 |
| 备注 | 用户备注 | 直接在单元格内编辑；长内容省略，悬浮或展开后查看全文 |
| 操作 | 打开本地 MOD 文件夹、展开详情、卸载 | 只保留带悬浮提示的图标；启停和编辑不在此列重复提供入口 |

启用按钮同时承担状态展示和启停入口：

- 使用 `aria-pressed`、图标、颜色和悬浮提示共同表达状态，不能只依赖颜色。
- 点击启用后先读取 Rust 部署计划。无冲突时直接启用；存在已启用 MOD 冲突时，确认框按冲突 MOD 分组显示名称和文件数量，展开后查看具体路径，用户确认后待启用 MOD 获得更高优先级。禁用仍直接执行，只清理 manifest 已记录的部署文件。
- 操作执行期间按钮显示加载状态并禁止重复点击。
- 冲突状态在名称旁使用警告图标提示，不增加独立冲突列，也不与启用状态混用。

批量工具条位于表格上方，只操作当前可见且已选择的 MOD：

- 右侧工作区整体滚动，各页面标题栏不固定；页面向下滚动 MOD 长列表时，批量工具条越过标题栏后直接吸附在窗口内容上边缘，选择数量和批量命令始终可见。
- 支持逐项选择、全选当前结果和清空选择；启用列仍保持为最左列，选择列紧随其后。
- “批量启用”只提交所选未启用 MOD，“批量禁用”只提交所选已启用 MOD，“批量卸载”提交全部所选 MOD。
- 批量启用和禁用不弹确认；批量卸载汇总本地文件数量、当前启用数量和 MOD 名称，只确认一次。
- 一次批量操作只占用一个后台任务，Rust 按前端提交顺序逐项复用单项核心逻辑；批量启用时后处理的冲突 MOD 延续现有规则获得更高优先级。
- 批量操作不是事务。单项失败时保留此前已完成结果并继续处理后续项目，结束后汇总成功、跳过和失败数量；文件保护和排序清理等操作提示仍按 MOD 汇总显示。
- 选择至少两个 MOD 后可创建分支组；已在组内的所选 MOD 可移出分支组。创建分支组只改变组织关系，不启用、禁用或移动文件。

分支组在 MOD 库中作为与普通 MOD 并列的一级表格项：

- 组行使用普通表格列，展示一级序号、组名、所有分支汇总后的分类与替换信息、分支总数和已启用数量。
- 组名、分类和替换信息允许按内容自然换行并完整显示，不使用省略号或 `+N` 隐藏组级摘要。
- 组行没有独立启用状态；左侧按钮用于展开分支，操作列只提供禁用全部和卸载整个分支组。分支需要展开后逐项启用，避免误启用多个互相冲突的版本。
- 组名可在组行直接编辑。展开后的分支继续使用普通 MOD 行，可独立编辑、打开文件夹、启停、改绑和卸载。
- 组行分类单元格可直接编辑整个分支组：全部分支都具有的分类显示勾选，只有部分分支具有时显示半选；勾选或取消只批量增删该分类并保留各分支其它分类，“清空分类”才清除全部成员分类。新建分类可在创建后一次应用到所有分支。
- 组行拥有六点拖拽把手，拖动时所有成员作为连续块写入手动顺序；组内分支不单独拖拽，并使用 `2.1`、`2.2` 这类层级序号。
- 展开区域使用连续浅色背景和左侧组标识，最后一个分支后显示明确的组尾分隔线，避免与下一个普通 MOD 混淆。
- 搜索命中组名或任意分支时显示该组；冲突管理使用“组名（分支名）”区分参与者。
- 自动排序提供“分支组优先”开关，默认开启：开启时先显示分支组、再显示普通 MOD，关闭时两者按同一字段混排；组内分支始终保持当前手动相对顺序。用户可见文本采用中文自然排序，连续数字按完整数值比较，因此 `2` 排在 `10` 前。分类升序固定先显示防具、再显示武器，其余内置大类按既定顺序排列，子分类继承父分类顺序，多分类 MOD 取最靠前的大类；防具内部继续按游戏内外观装备菜单顺序排列。倒序反转分类顺序，任何浏览排序都不改变冲突优先级。
- “自动创建分支组”替代 MOD 库内重复的刷新按钮。两个单文件 MOD 部署到完全相同的路径时直接形成分支候选；多文件候选仍必须满足高文件路径覆盖率，且组内任意两项都通过相似校验。冲突和共同替换目标只作为说明，不单独触发建议。界面显示所有成员真正共有的文件数、组内最低相似度、名称相似度和导入来源；超过 16 个成员的候选不显示。候选默认不勾选，只有用户选中并确认后才创建分支组。
- 从任意页面拖入文件夹或压缩包后，如果识别到多个候选分支，界面自动切换到“导入 MOD”并滚动、聚焦到分支选择区；不要求用户再从侧栏寻找候选结果。

名称和备注采用提交式行内编辑，而不是每次输入都写入磁盘：

- `Enter` 或失去焦点时保存，`Esc` 取消本次修改。
- 保存期间显示轻量状态；失败时保留草稿并在当前单元格提示错误。
- 表格行保持稳定高度，进入编辑状态不能推动相邻列或改变按钮位置。

## 分类系统

分类只有一套全局定义，不在界面上区分系统分类和用户分类，并支持顶级加一层子分类：

- 新 MOD 导入时，Rust 根据 `ModelReplacement.modelKind` 创建或复用初始分类，例如“防具”“投射器”；武器还会按 `subKind` 创建子分类，例如“武器·太刀”。这只是初始分配，不是永久只读规则。
- 用户可以给一个 MOD 选择多个分类，也可以移除、重命名或删除识别时生成的分类，并创建完全自定义的分类。
- 删除分类时，Rust 清除全部 manifest 对该分类 ID 的引用；删除顶级分类时，直接子分类保留并提升为顶级分类。如果该分类带有识别来源键，同时记录为已抑制，后续导入不会擅自重建它。
- 没有任何分类时显示“未分类”。新分类名称去除首尾空格后不能为空；同一父分类下不能重名，允许不同顶级分类拥有同名子分类。

分类筛选和全文搜索按任一已选分类匹配；筛选父分类时必须同时命中其全部直接子分类。分类修改只更新 MOD 元数据，不修改 MOD 文件、模型识别结果、启用状态或冲突排序。

设置页的“游戏文本语言”只控制替换信息、详情和模型改绑目标中的游戏名称。简体中文为默认值，切换为繁體中文后立即使用内置官方繁中名称索引；Acumod 的按钮、导航和操作提示仍保持简体中文。

## 表格详情

主表只展示日常管理所需摘要。点击展开按钮后，在当前行下方展示完整详情：

- 全部当前分类和替换目标。
- 游戏资源 ID、原始导入名称和来源信息。
- 文件数量、本地 MOD 文件夹和部署根目录。
- 当前启用冲突对象。
- 对武器、防具、随从防具、投射器/飞翔爪和发型显示改绑图标；人物语音和其它只读识别类别不显示该入口。

展开详情不使用嵌套卡片，并且同一时间允许用户展开多个 MOD。浏览排序只改变行显示顺序，序号按照当前浏览结果重新显示，不改变导入记录或冲突覆盖顺序；当前完整浏览结果可写入 `mod-library-order.json` 的手动顺序，依旧不参与部署。搜索和筛选只控制可见项，不会导致隐藏 MOD 在“应用排序”时丢失或移动到未定义位置。

模型改绑使用居中对话框，不离开 MOD 库页面。单分组只展示一个“替换模型”下拉框；多分组使用顶部标签切换，首项“恢复默认”表示恢复导入时目标。防具目标按游戏内外观装备菜单的普通/进阶、大师实际顺序显示；基础防具性别模型、`HARDUMMY` 和不可用幻化 ID 不进入下拉列表。五部位目标显示套装名，头套、耳饰、眼罩和围巾等单件外观直接显示完整“服装”名称，不允许因缺少部位后缀而退回纯模型 ID。飞翔爪的手动编号收进“其他飞翔爪编号”选项。点击“保存修改”后，前端在内部调用预览命令完成路径、MRL3、EVAM 和碰撞校验，只有关联或安全警告需要额外确认；不展示部署文件数量和技术预览。已启用 MOD 必须先禁用，本地 MOD 原始文件始终不修改。
