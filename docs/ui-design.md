# UI 设计

## 目标

Acumod 是面向持续管理 MOD 的桌面工具。界面优先让用户快速确认游戏状态、定位 MOD、完成导入和处理冲突；不做营销式首页，也不把高风险操作藏在抽象入口中。

本次 UI 架构切片只重组已有功能，不改变 Rust command、DTO、导入规则、部署规则或确认流程。

## 信息架构

```text
应用外壳
  ├─ 侧边导航
  │   ├─ MOD 库
  │   ├─ 导入 MOD
  │   ├─ 冲突管理
  │   └─ 设置
  ├─ 顶部状态区
  ├─ 主工作区
  │   ├─ MOD 库：已安装列表、启停、卸载、还原和操作结果
  │   ├─ 导入 MOD：文件夹或压缩包识别、候选分支和导入结果
  │   └─ 设置：游戏目录和应用信息
  └─ 悬浮 AI 助手：后续能力的独立窗口层
```

冲突管理与 MOD 库、导入 MOD、设置使用同一个工作区切换状态。它从侧边导航进入，只替换右侧主工作区，左侧导航和顶部状态区始终保留；用户可以直接从侧栏切换到任意其它页面。该页面专门展示已启用 MOD 的冲突组和组内覆盖顺序，未启用 MOD 的冲突不应进入该页面。

## 组件边界

- `AppSidebar`：展示应用名称、工作区导航、冲突数量和游戏目录状态；MOD 库、导入、冲突管理和设置统一发出 `WorkspaceView` 页面切换事件。
- `AppTopbar`：展示当前工作区标题、MOD 统计和刷新入口，不持有业务数据。
- `FloatingAgentPanel`：独立的悬浮窗口和最小化入口。本阶段只展示未接入状态，不提供伪造的对话或执行能力。
- `ModLibraryToolbar`：负责当前 Profile 选择、创建/重命名/删除入口，以及 MOD 搜索、筛选和浏览排序控件；只发出 UI 事件，不直接调用 Tauri。
- `ModLibraryTable`：负责列表序号、分类、替换信息、备注和图标操作；只接收已排序 DTO 并发出编辑、启停、打开目录和卸载事件。
- `App.vue`：仍作为当前阶段的业务协调层，保存跨工作区状态并通过 `src/api/*` 调用 Tauri；后续页面继续增长时再按工作区迁移到 `src/views/`。

## AI 悬浮窗口边界

AI 助手不会占用主导航中的一个页面，而是始终可从右下角打开的悬浮窗口。这样它可以辅助任何当前任务，但不会抢占 MOD 管理的主工作流。

未来接入 AI 时，窗口只能：

1. 读取已经由前端取得的展示数据，或请求 Rust 返回受控的查询 DTO。
2. 将自然语言意图转换为现有操作的受控请求。
3. 等待 Rust service 生成 `OperationPlan`，在主界面或窗口中展示计划、影响范围和风险。
4. 只有在用户明确确认后，调用既有的执行 command。

AI 不能直接操作游戏目录、本地 MOD 库或网络下载文件；传统 UI 尚不支持的功能，AI 也不能绕过实现。

## 视觉与交互规则

- 使用固定侧栏和可滚动工作区，保持列表、计划和文件路径在长内容下稳定可扫描；默认窗口为 `1320 x 760`，最小窗口为 `1040 x 660`。
- 页面区块使用克制的边框和小圆角，避免把整个页面切成漂浮卡片。
- MOD 库使用表格展示序号、名称、类别、替换信息和备注；不把文件数、部署根目录等实现细节作为主列表列。
- MOD 库顶部提供 Profile 下拉菜单和图标操作；创建 Profile 从当前启用状态与冲突顺序复制，切换前必须展示预览并确认。
- 分类、状态、冲突和替换目标检索只改变浏览结果；它们绝不改变冲突组覆盖顺序。
- MOD 行内操作使用带悬浮提示的图标按钮；危险操作继续依赖既有预览和确认信息。
- 窄窗口下侧栏转为顶部横向导航，主工作区保持单列；悬浮 AI 窗口缩小但不遮挡主要确认对话框。
- 本软件面向简体中文用户，游戏内物品、模型和术语优先显示官方简体中文名称；原始 ID 和路径作为辅助信息保留。
